# media-library

Локальна бібліотека медіа з семантичним пошуком. Картинки, відео, аудіо й
текстові нотатки складаються в одну бібліотеку й шукаються природною мовою —
за змістом, а не за іменем файлу.

Працює повністю офлайн: жодних хмарних сервісів, облікових записів і мережевих
запитів. Специфікація — `spec.md`, рішення й заміри — `PLAN.md`.

## Запуск

```
dist/media-library/media-library.exe
```

Ярлик є на робочому столі. Бібліотека створюється у `dist/media-library/data`
поруч із виконуваним файлом; моделі вшиті у збірку, інтернет не потрібен.

Перший запуск триває довше: близько 4 ГБ ваг читаються з диска у пам'ять
відеокарти. Вікно відкривається одразу, а пошук стає доступним за ~40 с — до
того в логу видно «Моделі завантажено».

## Оновлення

Нова версія — це заміна файлів застосунку. Тека `data` при цьому не чіпається,
і база сама доводиться до нової схеми при першому запуску.

```
python scripts/build.py                     # зібрати нову версію
python scripts/make_release.py --dry-run    # перевірити, що піде в архів
python scripts/make_release.py              # dist/media-library-<версія>.zip
```

`scripts/build.py` відкладає теку `data` вбік на час збірки й повертає назад:
PyInstaller із `--noconfirm` зносить теку призначення цілком, тож без цього
перезбірка на місці знищила б бібліотеку.

На боці користувача:

1. Закрити застосунок.
2. Розпакувати архів поверх наявної теки, погодившись на заміну файлів.
3. Запустити. Міграції відпрацюють самі, у лог піде запис про кожну.

**Теку `data` не видаляти й не замінювати** — у ній бібліотека, оригінали,
кадри, налаштування й база.

### Що робить міграція

`backend/app/db/migrations.py` тримає впорядкований список кроків і номер
схеми в таблиці `meta`. При старті база доводиться до номера, якого очікує код.
Схема новіша за код — застосунок відмовляється стартувати з явним поясненням,
а не псує дані.

Окремий випадок — зміна моделі ембедінгу. Розмірність вектора фіксується при
створенні таблиці, тож нова модель зі старими векторами несумісна. У цьому разі
векторний простір перебудовується, а записи стають у чергу на переобробку.
**Файли, теги й виправлені вручну транскрипції при цьому лишаються цілими** —
на це є тест (`tests/test_migrations.py`).

Версію застосунку й схеми видно внизу екрана налаштувань.

## Розробка

```
.venv/Scripts/python.exe -m backend.app.main
```

Фронтенд має бути зібраний:

```
cd frontend && npm install && npm run build
```

Під час роботи над інтерфейсом зручніше тримати бекенд і Vite окремо — тоді
працює гаряче перезавантаження:

```
.venv/Scripts/python.exe -m uvicorn backend.app.main:create_app --factory --port 8000
cd frontend && npm run dev
```

## Збірка

```
python scripts/prepare_models.py   # fp16-копії ембедерів (разово)
python scripts/build.py            # PyInstaller + ваги + підпис + перевірка
```

Готова збірка — близько 10 ГБ: ваги моделей (3.8 ГБ), CUDA-бібліотеки (2 ГБ) і
torch (2.9 ГБ). Такий розмір — свідомий обмін: усе працює офлайн і на
відеокарті з першого запуску.

Exe підписується самопідписаним сертифікатом (`scripts/sign.ps1`), довіреним на
рівня поточного користувача. Це прибирає «Невідомий видавець» на цій машині,
але **не** знімає SmartScreen на чужих — для цього потрібен комерційний
сертифікат. Втім, зібраний локально exe не має позначки «завантажено з
інтернету», тож SmartScreen на нього й не спрацьовує.

## Що всередині

| Шар | Де | Що робить |
|---|---|---|
| Інтерфейс | `frontend/` | React + Tailwind у системному вебв'ю |
| HTTP | `backend/app/api/` | Локальний FastAPI на випадковому порту |
| Інжест | `backend/app/ingest/` | Копіювання, дедуплікація, кадри, транскрибція |
| Моделі | `backend/app/ml/` | SigLIP2, E5, faster-whisper |
| Пошук | `backend/app/search/` | kNN у двох просторах, калібрування, підсвітка |
| Дані | `backend/app/db/` | SQLite + sqlite-vec, схема, міграції |
| Налаштування | `backend/app/settings_store.py` | Те, що змінює користувач |

### Моделі

| Задача | Модель | Обрано бо |
|---|---|---|
| Зображення й запити до них | `siglip2-large-patch16-256` | 76% Recall@1 проти 71% у base — замір на реальних файлах |
| Тексти й транскрипції | `multilingual-e5-base` | мультимовність, прийнятний розмір |
| Мовлення | `faster-whisper large-v3-turbo` | ~9 запитів із 13 проти 3-4 у `small` |

Ваги ембедерів зберігаються у fp16. Заміряно: Recall@1, Recall@3 і MRR
збігаються з fp32 до третього знака, а збірка легшає на 2.3 ГБ.

### Деталі, які легко зламати

**Шаблон запиту в `embedders.py` — не косметика.** Український запит, поданий
SigLIP «як є», дає 28.6% Recall@1; той самий запит у нижньому регістрі всередині
`a photo of {}.` — 76.2%. Приберете шаблон — пошук по картинках зіпсується втричі.

**Мови ASR обмежені трьома.** Без цього Whisper на двомовних записах регулярно
визначає польську, іспанську й грецьку.

**Оцінки схожості калібруються по фоновому розподілу** (`search/calibration.py`),
а не нормуються в межах видачі. Нормування в межах видачі робить найкращий
результат кожної модальності стовідсотковим, і тоді картинка з транскрипцією
завжди в нічиїй — пошук по звуку перестає працювати взагалі.

**Поріг калібрування низький свідомо** (один вектор). Доки простір лишається
без калібрування, транскрипції систематично програють картинкам — їхні косинуси
живуть у зовсім іншому діапазоні. На бібліотеці з одним відео пошук по звуку
через це не працював узагалі.

**Переобробка не чіпає виправлені транскрипції.** `transcript_edited` — не
просто позначка в інтерфейсі: `pipeline.process_audio` за нею пропускає
розпізнавання й переганяє лише вектори.

**`vec0` не бачить `LIMIT`, переданий параметром** — потрібен явний `k = ?`.

**Фонове оновлення форми не перезаписує поля, які людина редагує.**
`AddScreen` тримає набір змінених полів; без нього транскрибція, що
доготувалася, затирала б набраний текст просто посеред редагування.

## Тести

```
.venv/Scripts/python.exe -m pytest tests -q
```

Жоден тест не вантажить справжні ваги — реєстр моделей підмінюється
детермінованими заглушками, тож увесь набір іде близько секунди.

Наскрізна перевірка на реальних файлах із `samples/`:

```
python scripts/smoke_e2e.py --images 20 --audio 40
```

Заміри, якими обиралися моделі: `scripts/bench_asr.py`, `bench_vision.py`,
`bench_prompt.py`, `bench_precision.py`.
