# Специфікація — media-library

Проєкт є десктоп рішенням для збереження і пошуку по медіа (картинка, відео, аудіо, текст).

Працює повністю локально: без хмарних сервісів, без облікових записів, без мережі (крім одноразового завантаження моделей).

Флоу лише 2:

## 1. Зберегти дані

Оригінал файлу **копіюється** у теку бібліотеки застосунку. Бібліотека самодостатня: переміщення або видалення вихідного файлу її не ламає.

**1.1 Картинка** — просто зберігаємо (разом із ембедінгом зображення).

**1.2 Відео** — зберігаємо і локальною моделлю розпізнавання мовлення робимо субтитри з голосу (лише укр, рос та німецька мови), показуємо в полі «Транскрибція» те, що вийшло. Юзер може виправити або залишити як є і зберегти. Пошук — по ембедінгу транскрибції. Додатково зберігаємо кілька кадрів як картинки для ефективнішого пошуку — не кожен фрейм, а обмежена вибірка по зміні сцени.

**1.3 Аудіо** — так само як із відео, тільки без фреймів.

**1.4 Текст** — просто ембедінг тексту для пошуку. Ввід: текст, вставлений у застосунок, або файли `.txt` / `.md`.

**1.5 Лейбл і теги**

- **Лейбл** — підставляється автоматично за детермінованим правилом (без моделей) і залишається редагованим:
  - медіа-файли → ім'я файлу без розширення;
  - текст і транскрибція → перші ~8 слів.
- **Теги** — проставляються вручну з керованого списку. Список наповнюється в окремому екрані-адмінці (додати / перейменувати / видалити тег). Довільні теги «на льоту» не створюються. Теги можуть бути відсутні — запис зберігається без них.

Автоматичної генерації лейбла чи тегів моделями немає.

## 2. Пошук

2.1 Вводимо пошуковий запит.

2.2 Є фільтри: по типу (з пункту 1), даті створення, тегам.

2.3 Пошук по ембедінгах з пункту 1 видає всі знайдені записи з відсотком схожості. У картці результату: фрейм або зображення (якщо є), перші N слів, лейбл.

2.4 Можна натиснути, щоб прослухати/переглянути повністю.

**2.5 Пошук по фразі.** Окрім пошуку за змістом, працює пошук конкретної фрази
чи слова в транскрипціях і текстах — із допуском на помилки розпізнавання.
Якщо ASR почув «Купила я кока-колы за евро», запит «купила кока колу за євро»
все одно має знайти цей запис. Дослівні збіги позначаються в картці окремо.

**Нюанс ранжування.** Результати приходять із двох різних векторних просторів: зображення — з простору мультимодальної моделі, тексти й транскрибції — з простору текстового ембедера. Їхні значення схожості напряму непорівнювані. Перед злиттям у спільний список оцінки нормалізуються в межах кожної модальності, інакше спільний рейтинг брехатиме.

# Технічна сторона

Вимоги: усе має бути легким і працювати на десктопі. Цільове залізо — RTX 4060; CPU-режим має лишатися робочим, хай і повільнішим. Жодного Docker і жодних серверів, які треба піднімати окремо.

## Ухвалені рішення

| Питання | Рішення |
|---|---|
| Застосунок | Python (FastAPI локально) + React/Tailwind у системному вебв'ю через `pywebview`. Один процес, без IPC між мовами. |
| Сховище й вектори | SQLite + розширення `sqlite-vec`. Один файл на диску, ставиться через pip. Окрема векторна БД не потрібна. |
| Розпізнавання мовлення | `faster-whisper`, модель обирається в налаштуваннях. Мови обмежені: uk / ru / de. |
| Ембедінг зображень і крос-модальний пошук | Дві моделі одночасно: їхні помилки не збігаються, і разом вони точніші за кожну окремо (81% проти 76% Recall@1 на реальних файлах). Обрано заміром — див. README. |
| Пошук фрази | Повнотекстовий індекс SQLite для відбору кандидатів плюс нечітке зіставлення фрази з вікнами тексту. Окремих сервісів не потребує. |
| Ембедінг текстів | Мультимовна текстова модель сімейства E5. |
| Кадри з відео | Відбір по зміні сцени з жорстким лімітом кількості на відео. |
| Мова інтерфейсу | Українська. |
